## 供应链：why-is-node-running 信任降级处置

升级 Vitest 5.0.2 时，pnpm 信任策略（`trustPolicy: no-downgrade`）拦截其依赖 `why-is-node-running@3.2.2`：该版本（2025-01-08 发布）缺失 provenance attestation，而更早版本均有。

处置过程：

1. 下载 3.2.1 与 3.2.2 两个 tarball 逐行比对：差异仅为 `WeakRef` 内存泄漏修复与 V8 stack trace API 弃用适配（`getFileName()` → `prepareStackTrace` 收集），无网络行为、无混淆、无可疑代码。
2. 结论为良性维护版本，按模板既有先例（`million@3.1.11`、`semver@6.3.1`）加入四套前端 `pnpm-workspace.yaml` 的 `trustPolicyExclude`。

不阻塞模板使用；后续若发布带 provenance 的 3.2.3+，可从白名单移除该条目。

## 注意事项

- 后端本地验证遇到两个环境问题（均为本机环境所致，与升级内容无关，CI 不受影响）：
  1. 全局 `~/.m2/settings.xml` 的 `<localRepository>` 指向不存在的 `/opt/maven_repository`，且其配置的公司私服（191.168.7.39:8088）当前不可达，逐工件等待超时极慢。本次以最小 `fast-settings`（纯 aliyun 镜像 + 本地仓库覆盖）执行，即 README/operations 认可的本地加速方式。
  2. 本机 Docker 为 Colima（virtiofs），其共享目录刻意排除 `~/.colima`，导致 Testcontainers ryuk 边车无法挂载/连接 docker socket，`ApplicationContextTest` 3 个用例失败。经诊断（直接挂载、/tmp 符号链接两种方式均无法代理 AF_UNIX connect）后，以 `TESTCONTAINERS_RYUK_DISABLED=true` 本地重跑通过：真实 MySQL/Redis 容器、Flyway、应用上下文与全部 98 个用例均实际执行。CI（GitHub Actions 原生 Docker）不涉及此问题，无需改动模板。
- React SSR 维持的 ESLint 9 线已被上游标记为不再支持；在 `eslint-plugin-react` 发布 ESLint 10 支持前这是已知接受的风险，AGENTS.md 已记录复核方法与日期。
- `why-is-node-running@3.2.2` 已凭 tarball 审查证据加入信任白名单；待带 provenance 的新版本发布后建议移除该条目。
