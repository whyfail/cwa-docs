# 2026-10-19

## 更新概览

- React SSR 模板：ESLint `9.39.5` → `10.13.0`，采用现有 `eslint-config-next@16.4.0` 的官方兼容处理。
- 为三个精确插件版本补充 ESLint peer 范围，严格冻结安装及 `pnpm peers check --json` 通过。
- React SPA、Vue 3 SPA、Vue 3 SSR 与 Spring Boot：本次无依赖变化。
- React SSR 验证：类型检查、无缓存 lint、29 个单元与组件测试、覆盖率、13 个组件测试守卫、生产构建及 4 个 E2E 用例全部通过。

## React SSR 模板 (vite_react_ssr_init)

### 依赖版本变更

| 依赖 | 旧版本 | 新版本 | 类型 | 影响说明 |
| --- | --- | --- | --- | --- |
| eslint | ^9.39.5 | ^10.13.0 | major | 迁移到官方仍维护的 ESLint 10 主线，更新核心解析、作用域与缓存依赖 |

唯一发生版本变化的直接依赖为 ESLint。Next.js、`eslint-config-next`、React、TypeScript、Tailwind 插件、Node 与 pnpm 基线均保持原值。

### 兼容处理

[Next.js 官方说明](https://nextjs.org/docs/app/guides/upgrading/version-16#installation-fails-after-upgrading-eslint)明确指出，`eslint-config-next@16.4.0` 起支持 ESLint 10。现有配置包含旧 React/import 规则上下文 API 以及 Babel scope manager 的兼容处理，因此保留官方 `core-web-vitals`、TypeScript 配置和 Tailwind 规则。

以下插件的上游 peer 声明仍未包含 ESLint 10：

| 插件 | 当前版本 | 项目级修正 |
| --- | --- | --- |
| eslint-plugin-react | 7.37.5 | 在原 ESLint peer 范围后补充 `^10.13.0` |
| eslint-plugin-import | 2.32.0 | 同上 |
| eslint-plugin-jsx-a11y | 6.10.2 | 同上 |

使用 [pnpm 官方支持的 peer overrides](https://pnpm.io/settings/dependency-resolution#overriding-peer-dependencies)，在 `pnpm-workspace.yaml` 中按“精确插件版本 > eslint”限定修正范围，并将配置记录进锁文件。保留严格 peer 检查及既有供应链策略。

除了对现有源码运行 lint，还用三组故意违规的内存样例检查规则行为：`react/jsx-key`、`import/no-anonymous-default-export`、`jsx-a11y/alt-text` 均正确检出对应问题，且未出现插件加载或运行错误。
